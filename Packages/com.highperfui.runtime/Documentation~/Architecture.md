# Unity 虚拟节点框架：实现架构

版本：0.3.0-preview.3。这里描述可核对的实现，不把早期“终极框架”设想全部标为完成。

## 业务问题与分层

复杂物品模板的问题不只有数量。循环列表限制了同时存在的 Item，但每个完整模板仍带着锁定、选中、稀有词条、精通、套装、限时等分支；频繁绑定还会重复写属性，异步结果则可能写回已经换主人的实例。

```text
项目业务模型 / 项目资源系统
        | 稳定 ID、目标状态、资源提供者
        v
集合层 FixedVirtualizedScrollList ------> UiViewPool / UiPoolBudget
        | 绑定和精准刷新                      | 租约
        v                                    v
展示层 IncrementalUiView <-----------> PooledUiView / UiScope
        | 脏字段                         | 提交、布局、交互门禁
        v                                v
片段层 LazyFragmentHost -----------> UGUI 对象与项目适配组件
        | 依赖、按需实化                   ^
        +------ UiRuntime / Scheduler ----+
```

业务 Sample 位于 Samples~，不是 Runtime 的编译依赖。框架不接管交易、奖励权威状态或页面路由。

## 四个必须守住的不变量

1. **身份分离**：index 是当前位置，DataId 是业务身份，BindingGeneration 是本实例的内容版本，LeaseId 是租借版本，Scope token 是外部工作生存期。排序不意味着换人，归还后重租一定意味着旧工作失效。
2. **按需语义**：隐藏和查询不创建；Require 是显式的同步兜底，SetVisible 是调度请求；失败不伪装成已就绪。
3. **交互就绪**：Scope 存活、状态已提交、原生布局已确认、必要片段全部存在，四者同时成立才开启交互。
4. **副作用区分**：属性目标状态可以合并；支付、音效、一次性业务操作不能通过脏字段“最后写入者胜出”。UiCommandQueue 保序展示命令，业务幂等另行实现。

## 调度与一致性

FrameBudgetScheduler 使用四优先级加权轮转，权重为 4:3:2:1。每帧只处理入帧时的队列快照，新工作与续步进入后续帧，避免自重入独占本帧。WorkKey 合并同一实例/绑定/操作的待执行工作；取消和失效检查阻止旧工作提交。

预算由 Stopwatch 检查，是**软预算**。ExecuteStep 之间可暂停，单次 Instantiate、AddComponent 或引擎调用内部不可中断。一个超大 prefab 仍可能超预算；必须拆分合理片段并记录最大单步和超预算次数，不能只展示平均调度耗时。

调度器入队、取消、键查找平均 O(1)，执行 O(本帧出队步数)，可取消项在被消费前仍占队列槽位。OldestWaitFrames 是 O(待处理数) 的诊断读取，不应被业务反复读取。异常隔离后不自动重放副作用；持续过载只丢弃/拒绝可选低优任务，不自动丢掉可见和交互任务。

## 增量同步

IncrementalUiView 对字段 mask 做合并；ExecuteStep 先取 mask 快照，再执行 ApplyDirty。执行期间新产生的脏字段保留给续步，避免“清空 dirty”吞掉重入修改。派生类保存类型化目标状态，并比较已提交值，框架不通过反射遍历任意对象。

这是字段级增量同步，不是通用树 Diff，也不是全场景原子事务。布局确认、关键片段门禁与可选展示可能分帧完成；跨多个独立 View 的一致性由业务协调器设计。

## 列表与片段

RefreshItems 对变更 ID 建可复用集合，再扫描活跃 View，成本 O(变更数 + 活跃数)。RefreshStructure 重新计算可见 ID，按 ID 保留实例并映射新索引，不按旧索引误回收。**结构刷新不代替内容刷新**：同一 ID 的强化属性也必须发送内容通知。

片段描述先校验 ID、模板、依赖和循环。实化前后都检查绑定，SetActive 引发的重入也不例外。缺失模板使必要片段保持失败/门禁关闭；显式重试后才能恢复。片段缓存是显式有界策略，TrimHidden 释放非必要隐藏分支；它不等于全场景字节预算，更不等于三级 HOT/WARM/PROTO 池。

## 资源与池化

AsyncSpriteSlot 同时验证请求序号和绑定 token。取消是尽力减少工作；迟到结果仍必须释放资源租约。提供者适配项目的 Addressables/AssetBundle 等资源系统，并把回调送到 Unity 主线程；本包不自带真实 Addressables 集成。

UiViewPool 拒绝重复归还和错误池归还，清理放在失效 Scope 和项目的 OnReturn 契约中。CaptureLease 能判断是不是当前租约，**Return(view) 本身没有 token 参数**，所以禁止旧异步回调直接归还手中的实例。池数量限制和共享空闲数量预算不代表精确原生内存限制。

## 深度与边界

技术难点在“优化之后仍然正确”：跨帧、排序、重绑定、模板失败、回收再租、取消后迟到、实化回调重入。它们都应有失败路径测试，而不是靠增加一层抽象来体现复杂度。

未实现：透明 Unity API 代理、模板编译器、动态高度列表、自动字节预算、硬抢占、完整 React-style Fiber、全局事务提交、移动端/IL2CPP 认证。九分只能来自目标项目上的收益和工程验证，不能从模块数量自动得出。
