# 验证协议与发布边界

目标环境：Unity 2022.3.60f1c1，Windows UGUI。具体通过数与 tarball 指纹以交付目录 ValidationResults.md 和 Evidence 为准，不预写“全部通过”。

## 安装验证

1. 生成实际 .tgz 后，在独立 Unity 工程的 manifest 引用它，而不是引用原源码文件夹。
2. 不导入业务 Sample，添加 testables 后跑包的 EditMode/PlayMode 测试，证明 Runtime 不依赖业务。
3. 导入三个 Samples 后再编译，运行业务模型与真实指针点击测试；打开军备场景验证画面。
4. 发布源文件、测试 XML、编辑器日志、内容指纹与兼容性边界。不把旧版本日志充作本版本安装验证。

## 正确性覆盖

调度合并/取消/公平性/异常；片段依赖与模板失败；归还重租与绑定代际；取消后迟到的资源释放；稳定 ID 结构重映射与内容刷新；交互门禁；业务强化资源、重复领取和存档恢复；诊断导出失败后恢复输入及玩家进度。

## 性能协议

A 是全量完整卡片，B 是池化循环列表完整卡片，C 是按需片段。B 不是手写到极限的分类型模板工厂，这个边界必须保留。正式结论以独立进程轮换、同设备、同分辨率、相同数据与操作为前提；同进程快速按钮只做功能预检。

首屏时间从共享界面/美术准备后开始，直到可见 View、关键片段、布局与图标就绪，不是进程冷启动。整帧分位值包含帧率上限、渲染和系统噪声；绑定 CPU 只归因于 Item 绑定/属性应用，不能代表完整 UI CPU。阶段切换可能夹带前一阶段未完成的工作，不应拿微小阶段差异作绝对结论。

NativeNodes 统计集合下所有 Transform（含池里闲置节点），不是原生字节数。MonoBytes 是全局托管堆端点；PeakAllocatedBytes 是每个记录帧的全局已分配内存高水位，仍不包含帧内瞬态峰值，也不是归因到 UI 实例的独占峰值。GC 字段是采样区间分配字节数，不是 GC 次数或停顿时长。

性能测试与 Unity 编辑器测试不要并行。失败、超时、OOM、状态摘要不一致和空画面都必须记录，不能只挑完成的 C 数据。少于1000帧不报告 P99。

## 尚待目标项目验证

移动设备、IL2CPP、动态高度/复杂布局、多 Canvas、资源热更新、真实 Addressables、多页面并发、长期会话与项目级内存压力。预发布包不将这些门槛默认为已满足。
