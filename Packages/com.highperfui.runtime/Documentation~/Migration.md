# 从原虚拟节点思想迁移到 Unity UGUI

## 保留的思想，不机械照搬引擎接口

原方案的价值是延后不需要的真实子树、隐藏不触发创建、必要访问同步兜底，以及相同结构复用。Unity 中 Transform、Awake/OnEnable、动画、布局、资源句柄都有副作用，不能只用一个代理对象假装它们不存在。

| 原思路 | Unity 落点 | 必须额外解决 |
|---|---|---|
| 虚拟子树 | 独立片段 prefab + LazyFragmentHost | 模板依赖、Unity 销毁对象的 null 语义 |
| 首次访问实化 | Require / 批量显式 Require | 同步路径不能伪称受严格帧预算约束 |
| 隐藏不创建 | SetVisible(false)、GetIfCreated | 查询与命令分开，避免隐式副作用 |
| 调用回放 | 类型化目标状态 + 脏字段 | 普通属性可合并，一次性命令必须保序 |
| 结构复用 | UiViewPool + 稳定 ID 集合 | 旧回调、监听、图标和布局状态重置 |
| 分帧创建 | UiRuntime + 小步工作 | 只能在步骤之间暂停，原生操作不可硬抢占 |

## 分阶段接入真实项目

1. 用 Profiler 找到真正超预算的界面，拆出“实例数量、模板复杂度、重复绑定、布局、资源”各自耗时。不是所有 UI 问题都适合虚拟节点。
2. 先只替换一个重复复杂 Item，复用项目数据和资源系统，保留旧实现作为开关基线；不要第一步改整套 UI 路由。
3. 实现 IVirtualizedItemSource，提供稳定唯一 ID。固定列表/网格接入 FixedVirtualizedScrollList，变高度暂时继续使用项目原有列表。
4. 展示单元继承 IncrementalUiView，将目标状态映射为少量字段 mask；不要把资源加载、业务发奖或网络请求塞进 ApplyDirty。
5. 只把成本明显、非必现的独立子树拆成片段。整体动画和 LayoutGroup 强耦合区域先保持完整，避免碎片化带来的布局震荡。
6. IUiSpriteProvider 接项目资源系统，Scope.Track 接事件解绑/动画停止。用迟到回调、重租和关闭界面测试先验证正确性。
7. 再与“已池化的循环列表”比较 CPU、原生节点、GC、打开耗时和整帧分位值。收益不明显就不扩大接入范围。

## 接入侵入性

这是显式、渐进、可回退的低侵入方案，不是无需修改旧组件的绝对零侵入系统。需要提供稳定 ID、View 绑定/重置契约和资源适配。框架不替项目自动发现全部外部事件、第三方动画和隐藏副作用。

正式项目应在自己的 UI 路由层配置实现开关，按页面/机型灰度；本包没有假装提供一套万能远程配置或自动热切换。回退不能丢掉业务模型，只替换展示适配层。
