## 独立进程性能实测

协议：初始1000条业务记录，1440×900，每次1200工作负载帧，A/B/C 轮换顺序，各计划3次。界面共享外壳和美术准备后才开始测打开时间，**不是进程冷启动**。A 全量完整卡片；B 池化循环列表完整卡片；C 循环列表 + 按需片段/增量更新/调度。

原始记录在 `Benchmarks`，包含尝试信息、日志、JSON、CSV 和成功截图。9次尝试中有7份有效结果：A 第一次180秒超时；第二次退出码0但无结果，不能当作成功，原因未确认；第三次完成。B/C 各3次完成，业务摘要一致、可见状态及非空网格检查通过。`ValidateResults.ps1` 正确拒绝本轮完整验收，未生成全模式通过摘要。

下面是有效结果的描述性统计；A 只有一个样本，不与 B/C 中位数作正式收益比较。B/C 也仅3次，属于初步证据。

| 指标 | A（1次） | B（3次中位数） | C（3次中位数） |
|---|---:|---:|---:|
| 打开至可交互就绪 ms | 3257.01 | 410.82 | 596.66 |
| 整帧 P95 ms | 244.15 | 32.57 | 8.38 |
| 整帧 P99 ms | 360.82 | 38.07 | 12.52 |
| 集合中 Transform 数（含闲置池） | 33103 | 1324 | 726 |
| Item 绑定次数 | 16003 | 6760 | 2150 |
| 批量刷新阶段归因绑定 CPU 合计 ms | 1447.92 | 45.53 | 33.88 |
| 滚动阶段归因绑定 CPU 合计 ms | 0.00 | 621.42 | 728.92 |
| 采样区间分配字节 | 181951507 | 34637044 | 42525114 |
| 全局托管堆端点字节 | 204107776 | 16183296 | 12664832 |

**能支持的结论**：在这组业务/设备上，相对 B，C 的节点数约少45.2%、绑定次数约少68.2%，批量刷新阶段的归因绑定 CPU 约少25.6%；整帧尾延迟呈改善趋势。不能把 A→B 的循环列表收益全部归给按需节点。

**必须同时展示的退化**：C 打开时间约增加45.2%，采样分配字节约增加22.8%，滚动阶段归因绑定 CPU 约增加17.3%。Sample 使用激进的 `TrimHidden(0)`，减少常驻节点的同时会反复创建片段。框架支持缓存策略，是否保留热片段应由业务和目标机数据决定，本交付没有再做缓存参数消融来证明最优值。

2ms 是配置的协作式软预算，不是整帧保证。C 三次最大单步约22.46/28.84/34.78ms，每轮记录约658～663次超预算。同步 Require 与 Instantiate 不能被强行中断；当前 Sample 的立即实化路径明确存在预算突破。因此不能宣称“1000节点稳定2ms”或“全部指标优化”。

## 指标口径

- 节点数不是原生内存字节；托管堆和全局分配高水位不是该 UI 的独占内存或帧内峰值。
- GC 字段是采样区间分配字节，不是 GC 次数、GC 暂停时间或零分配证明。
- 绑定 CPU 只计 EquipmentCell 的 SetData/ApplyDirty。完整 Item prefab 创建、布局、渲染不在此计时内；C 在 ApplyDirty 内同步创建可选片段，该成本包含在内。因此不能声称这是完整 UI CPU，A 滚动阶段为0也不表示滚动没有渲染开销。
- 整帧分位数包含120fps上限、渲染、开屏阶段和系统噪声；三轮中位数不是跨设备统计置信结论。阶段边界可能夹带上一阶段的续步。
- 语义摘要和网格像素检查是自动化保护，不等于逐像素等价证明；实际业务交互另有 PlayMode 点击测试。

## 复现

推荐 Unity 2022.3 LTS，从 tarball 安装；在 Samples 页导入 SLG Armory Business，打开 `Scenes/Inventory.unity` 后 Play。

完整 ZIP 的 `VerificationProject` 已导入三个 Sample 和测试，不要重复导入。用 Unity Hub 添加该目录，或在解压根目录运行（先关闭该工程的编辑器）：

```powershell
& .\Scripts\RunUnity.ps1 -Editor 'D:\Unity\2022.3\Editor\Unity.exe' -Action EditMode
& .\Scripts\RunUnity.ps1 -Editor 'D:\Unity\2022.3\Editor\Unity.exe' -Action PlayMode
& .\Scripts\RunUnity.ps1 -Editor 'D:\Unity\2022.3\Editor\Unity.exe' -Action Build
& .\Scripts\Compare.ps1 -Executable '.\VerificationProject\Builds\Windows\HighPerfUI.exe' -Count 1000 -Repeats 3 -Frames 1200 -Output '.\LocalResults\Comparison-01'
```

Editor 路径替换为已安装编辑器。每轮用新输出目录，测试/构建/性能采样串行执行。比较脚本对任一超时、缺结果、语义不一致或空画面报失败；不要删除失败尝试来凑通过。ZIP 的 `Examples/Windows/HighPerfUI.exe` 可直接体验业务，但不是安装框架的必要条件。

## 发布边界与异常历史

当前是工程预发布包：可直接安装、可运行业务 Sample，有自动化回归和初步性能证据；不作为“已完成商业认证”或高级岗位面试通过承诺。

此前无图形模式的独立工程运行出现过退出挂起，即使 XML 通过也未计入本记录的验收；上表采用图形开启、正常退出的记录。额外在 D 盘交付工程使用相对 tarball 路径复跑时，98项测试 XML 通过，随后编辑器停在退出阶段；仅停止了本任务的该进程，退出码-1，**不计为整次验证通过**。原因尚未定位，其日志/XML 单独标为 `Evidence/ExcludedRuns/RelocatableProject`。交付脚本会拒绝非零退出/超时，不会拿通过 XML 掩盖异常。

早期并行编辑器/程序的试跑发生过 OOM，不用于本表。早期 OnDisable 测试夹具未真实触发回调，其失败不是有效 RED；修正夹具后验证重绑确实发生，生产保护未被移除。更早的调试资料保留在源工作目录。本交付 Evidence 将有效记录和额外的异常退出记录分目录保留，不混为同一通过结论。
