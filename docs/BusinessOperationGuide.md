# 军备整备中心：运行与操作

这是可交互的本地 SLG 军备业务切片，不是完整游戏，也不连接服务器。默认打开仓库，而不是实验室。

## 双击运行

- `RunDemo.cmd`：打开 Windows 程序，读取并自动保存本地进度。
- `RunFreshDemo.cmd`：使用固定初始数据体验，不读取或覆盖存档，适合面试演示。
- `OpenUnity.cmd`：使用本机 Unity 2022.3.60f1c1 打开 ReferenceProject；进入 Assets/Scenes/Inventory.unity 后点击 Play。
- 换电脑打开 Unity 时，在 Unity Hub 添加 ReferenceProject 文件夹。不要添加整个交付根目录。

## 五分钟演示

1. 在军备库浏览装备，按类型、名称、品质、战力筛选，查看不同品质的词条、精通、套装和锁定状态。
2. 点击装备，右侧显示与当前穿戴装备的战力差；穿戴后左侧槽位、总战力和套装防御一起更新。
3. 强化前先查看金币和精铁成本；确认后扣除资源并更新属性。资源不足、非装备、过期物品会被业务规则拒绝。
4. 锁定一件装备并勾选“仅锁定”，验证过滤后的列表继续正确刷新。
5. 进入奖励中心，领取一组混合奖励；装备、材料、英雄信物、限时补给进入同一个仓库，资源数变化。重复领取不会重复发放。
6. 正常模式关闭再打开，验证进度保存。无存档权限或校验失败时会保留原文件并显示错误，不静默清空。

预置数据是确定性演示数据，不是线上玩家数据。材料和英雄信物在本切片中可查看、收藏，但没有合成/招募消费链路。限时数据使用固定未来时间，不能解释为真实的“剩余24小时”。

## 性能对照是可选入口

点击右上角“性能对照”才显示诊断工具；“返回业务”收起。

- A 全量创建：直接为所有物品创建完整 UGUI 卡片，用作常见低效起点。
- B 循环列表：可见范围复用完整卡片，是实际应当比较的对象池列表基线。
- C 按需节点：同一套业务内容，使用可见列表、按需片段、稳定 ID 精准更新及生命周期隔离。

"运行三组对比"是同进程快速检查，使用独立的临时业务模型，结束或导出失败后恢复原有进度，不用于正式性能结论。面试建议使用 RunFreshDemo.cmd。

正式测试命令：`powershell -ExecutionPolicy Bypass -File Tools/Compare.ps1 -Repeats 10 -Frames 1200 -Output Benchmarks/new-run`。
测试会启动真实渲染窗口，轮换 A/B/C，每次独立进程；不要同时操作测试窗口。详见 ProductBenchmarkReport.md。

## 接入另一个 Unity 项目

Package Manager > Add package from tarball，选择 Deliverables 下的 `com.highperfui.runtime-0.3.0-preview.1.tgz`。
框架本身没有军备业务依赖；本地项目也可通过包的 package.json 接入。运行示例、业务实现与框架分别位于 ReferenceProject 和 Packages。

这是显式接入的预发布包，不是能透明代理任意旧 MonoBehaviour 的“绝对零侵入”系统；已有业务需要提供稳定 ID、绑定接口和片段描述。
